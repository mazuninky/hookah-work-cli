# hw command reference

Generated by `hw generate-docs` from the clap command tree; do not edit by hand.

## hw

Read-only command-line client for the HookahWork CRM API.

hw only reads: every command is a GET request, plus the two non-mutating POSTs the API
needs for logging in and for searching a client. Nothing in the CRM is created, changed
or deleted.

**Usage**

```text
Usage: hw [OPTIONS] <COMMAND>
```

**Options**

- `--verbose, -v` — Increase logging verbosity (-v, -vv, -vvv); logs go to stderr
- `--quiet, -q` — Print only errors to stderr: no hints, no warnings
- `--config` — Configuration file [default: $XDG_CONFIG_HOME/hw/config.toml or ~/.config/hw/config.toml]
- `--profile, -p` — Profile from the configuration file to use
- `--crm` — CRM to talk to: subdomain (demo), host (demo.hookah.work) or base URL
- `--format, -F` — Output format
- `--no-color` — Disable colored output (NO_COLOR is honoured too)
- `--no-pager` — Do not page console output (also HW_NO_PAGER=1)
- `--jq` — Filter the JSON result with a jq expression before formatting
- `--template` — Render the result with a minijinja template instead of --format
- `--retries` — Retries for rate limiting (429), server errors (5xx) and network failures; 0 disables

**Subcommands**

- `ref` — Reference data: settings, tables, payment methods, employees, services, bonus levels
- `product` — Products and product categories
- `storage` — Storages and purchases
- `client` — Clients: list, groups, visit history, lookup
- `booking` — Bookings: daily list, timetable, single booking, device bookings
- `sale` — Sales at tables or over a business day
- `hookah` — Hookahs served at tables or over a business day
- `report` — Daily reports: expenses, credits, bonus points
- `analytics` — Period summaries of hookahs and sales
- `menu` — Public electronic menu (works without a token)
- `api` — Send a raw GET request to any API path
- `auth` — Log in and manage the stored API token
- `config` — Inspect and manage configuration profiles
- `completions` — Print a shell completion script
- `self` — Check for and install hw updates from GitHub Releases

### hw auth

Log in and manage the stored API token

**Usage**

```text
Usage: hw auth [OPTIONS] <COMMAND>
```

**Subcommands**

- `login` — Store an API token for a CRM (prompts on a terminal; flags read stdin)
- `status` — Show the profile, CRM, token source and whether the token works (exit 4 if not)
- `token` — Print the resolved API token, for scripts
- `logout` — Remove the profile's stored token (the profile itself stays)

#### hw auth login

Store an API token for a CRM and make it usable by every other command.

On a terminal, hw asks for the CRM (unless --crm, HW_CRM or the profile names it), then
for an API key or for an email and password, and last where to save the token (unless
--storage is given). A CRM director generates the API key at
https://<crm>.hookah.work/v2/settings/users (hw prints the exact address).

Scripts and CI pass a flag and pipe the secret on stdin, never on the command line:
  --with-token                  one line of stdin is the API key
  --email E --password-stdin    one line of stdin is the password of CRM user E;
                                hw exchanges it for the token via POST /api/login
Without a flag and without a terminal (stdin and stderr), login fails with exit 5.

The token is checked with GET /api/settings before it is saved where --storage says.
Without --storage, a terminal login asks (preselecting the profile's current storage);
otherwise an existing profile keeps its storage and a new one uses the config file
(api_token, 0600 permissions). Saving to one place removes the profile's token from the
other.

The profile name is --profile; without --crm, the default (or only) existing profile;
otherwise the CRM's first host label (demo for demo.hookah.work).

**Usage**

```text
Usage: hw auth login [OPTIONS]
```

**Options**

- `--with-token` — Read the API token from the first line of stdin instead of prompting
- `--email` — Email of the CRM user to log in as (with --password-stdin)
- `--password-stdin` — Read the password from the first line of stdin instead of prompting (with --email)
- `--storage` — Where to save the token [default: the profile's storage, else config; a terminal login asks]

#### hw self update

Download a hw release from GitHub and replace the running hw binary with it.

Installs the latest release, or the one --to names. The SHA-256 checksum of the release
archive is verified against the .sha256 file published with it before anything is unpacked;
on a mismatch nothing is replaced. The new binary takes the old one's place in a single step
(on macOS it is ad-hoc signed first, so keychain access keeps working).

Prebuilt releases exist for x86_64 Linux (glibc), Apple Silicon macOS and x86_64 Windows;
elsewhere build from source with cargo install. A hw installed by Homebrew, Nix or the system
package manager is left alone: update it there. Nothing is sent to the CRM.

**Usage**

```text
Usage: hw self update [OPTIONS]
```

**Options**

- `--to` — Version to install instead of the latest release: YEAR.WEEK.BUILD, e.g. 2026.41.1 or v2026.41.1
- `--allow-downgrade` — Let --to install a version older than this hw
